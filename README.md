# coCN · 中文编程语言

`coCN` 是一门用 C 实现的中文编程语言（`co.c` 单文件，约 6300 行，零第三方依赖）。
它既是一门**通用编程语言**（静态类型标注、模块、模式匹配、推导式、真并发、文件 IO、高阶函数），
又具备**系统编程能力**（完整位运算、进制字面量、字节级视图），
还能**编译成独立的原生二进制**（`co --编译`，不依赖解释器，实测比解释执行快 7.7×，递归负载快 25×），
也内置**张量类型与自动求导引擎**，可以用接近伪代码的中文写出可训练的神经网络。

> 设计取向：语义正确性优先于特性数量。任何"看起来能跑但结果是错的"行为都按缺陷处理——
> 例如 `"abc" == "xyz"` 必须为 `假`（而不是被当成字符串拼接后恒为真），`y = -x` 必须不改动 `x`。

## 1. 构建与测试

```bash
make              # 编译生成 ./co
make test         # 功能套件 + 错误路径 + 全部例子（一键回归）
make native       # 原生通道门禁：同源码两条通道输出必须逐字节一致
make bench        # 性能基准：先验结果一致，再报加速比
make asan         # ASan + UBSan：要求零泄漏、零未定义行为
make asan-error   # 错误路径的越界/UB 检查（错误分支最容易藏内存问题）
make tsan         # ThreadSanitizer：要求并发用例零数据竞争
make check        # 提交门禁 = test + native + bench + asan + asan-error + tsan
./co 例子/异或网络.co
./co 例子/位运算与系统编程.co
```

两种运行方式：

```bash
./co 程序.co                     # 解释执行
./co --编译 程序.co 我的程序     # 编译成独立二进制
./我的程序                       # 直接运行，不需要 co
./co --生成C 程序.co 程序.c      # 只产出 C 源码，接进自己的构建
```

依赖：仅 `gcc`、`-lm`、`-lpthread`。`--编译` 额外需要环境里有 `cc`。

## 2. 数据类型

| 类型 | 标注关键字 | 字面量 | 说明 |
|------|-----------|--------|------|
| 整数 | `整数` | `42` `-7` `0xFF` `0b1010` `0o777` `1_000_000` | 64 位；支持十六/二/八进制与 `_` 分隔符，越界字面量在词法期报错 |
| 浮点 | `浮点` | `3.14` | 双精度；整数可隐式加宽为浮点 |
| 布尔 | `布尔` | `真` `假` | **独立一等类型**，打印为 `真`/`假`，不是 `0/1` 别名 |
| 字符串 | `字符串` | `"你好"` | UTF-8，**按字符**索引与取长度 |
| 列表 | `列表` | `[1, 2, 3]` | 可异构、可嵌套 |
| 字典 | `字典` | `{"键": 值}` | 字符串键 |
| 张量 | `张量` | `张量([[1,2],[3,4]])` | 支持广播与自动求导 |
| 函数值 | `函数值` | 函数名本身 | 可作参数传递（高阶函数） |
| 数字 | `数字` | — | 整数或浮点（标注用） |
| 任意 | `任意` | — | 关闭该处类型检查 |
| 空 | `空` | `空` | 无值。`空` 既是类型标注也是字面量，打印为 `空`，是假值 |

类型标注是**渐进式**的：不写就是动态，写了就在赋值/传参/返回处强制检查。

```co
整数 n = 10
布尔 开关 = 真
函数 安全除(浮点 a, 浮点 b) -> 浮点
    若 b == 0.0 返回 0.0
    返回 a / b
结束
```

## 3. 语法速查

| 用途 | 关键字 | 示例 |
|------|--------|------|
| 变量 / 常量 | `让` `变量` `常量` | `让 x = 3` |
| 函数 | `函数` `返回` `结束` `->` | `函数 平方(整数 a) -> 整数 返回 a*a 结束` |
| 输出 | `输出`（无括号，逗号分隔） | `输出 "结果=", x` |
| 条件 | `如果`/`若` `则`/`那么` `否则如果`/`否则若` `否则` `结束` | `若 a > b 那么 ... 否则 ... 结束` |
| 当循环 | `当` `循环` `结束` | `当 条件 循环 ... 结束` |
| 计数循环 | `对于` `从` `到` `步长` `循环` `结束` | `对于 i 从 1 到 10 步长 2 循环 ... 结束` |
| 跳出 / 继续 | `跳出` `继续` | `继续` 只跳过本次迭代 |
| 逻辑 | `且` `或` `非` | 短路求值，结果为布尔 |
| 位运算 | `&` `\|` `^` `~` `<<` `>>`（或 `按位与` `按位或` `按位异或` `按位取反` `左移` `右移`） | 见 §3.1 与 §3.7 |
| 模块 | `导入` | `导入 "标准库"` |
| 模式匹配 | `匹配` `是`/`情况` `默认` `结束` | 见 §3.4 |
| 推导式 | `对于` `于`/`在` `如果`/`若` | 见 §3.3 |
| 并发 | `并发` `等待` | 见 §3.5 |
| 注释 | `#` | `# 这是注释` |

> `输出` 是特例：`输出 表达式1, 表达式2`（**无括号**）。其余函数调用都用括号。

### 3.1 运算符

| 运算符 | 语义 |
|--------|------|
| `+` `-` `*` | 数值算术；`+` 还可用于**字符串拼接**与**列表拼接** |
| `/` | **真除法**：`3 / 2` = `1.5`；除零报错 |
| `//` | 向下取整整除：`7 // 2` = `3`，`-7 // 2` = `-4` |
| `%` | 取模（支持浮点），除零报错 |
| `==` `!=` | **结构化判等**：数值跨类型、字符串逐字节、列表/字典/张量递归比较 |
| `<` `>` `<=` `>=` | 同类可比：数值之间、字符串字典序、列表字典序；跨类型比较**报错**而非静默出错 |
| `-x` | 取负，**返回新值**，绝不修改源变量或容器元素 |
| `x[i]` | 索引：列表/字符串支持**负索引**（`-1` 为末位）；字符串按字符切分不会切碎汉字 |
| `&` `\|` `^` | 按位与/或/异或；**仅接受整数与布尔**，浮点参与直接报错 |
| `~x` | 按位取反（64 位补码，`~0` = `-1`） |
| `<<` `>>` | 左移 / **算术**右移；位数为负或 > 63 报错（不落入 C 的未定义行为） |

**比较结果一律是布尔**。字符串只接受 `+` 拼接，`"a" - 1` 这类会明确报错。

优先级与 C 完全一致（低 → 高）：

```
或 < 且 < | < ^ < & < == != < < > <= >= < << >> < + - < * / // % < 一元 - + 非 ~ < [] 调用
```

所以 `1 << 2 + 3` 是 `1 << 5` = `32`，`1 & 2 == 2` 是 `1 & 真` = `1`——与 C 逐字对应，不需要重新背表。

### 3.2 字符串（UTF-8 感知）

```co
断言相等(长度("你好世界"), 4)          # 按字符计数，不是字节
断言相等("你好世界"[0], "你")           # 按字符索引
断言相等("你好世界"[-1], "界")          # 负索引
断言相等(反转("你好"), "好你")
断言相等(分割("甲、乙、丙", "、"), ["甲", "乙", "丙"])   # 多字节分隔符
```

### 3.3 推导式

```co
列表 平方表 = [x * x 对于 x 在 范围(1, 6)]                    # [1,4,9,16,25]
列表 偶数表 = [x 对于 x 在 范围(1, 11) 如果 x % 2 == 0]        # [2,4,6,8,10]
字典 词长 = {w: 长度(w) 对于 w 在 ["苹果", "西瓜"]}            # 单变量形式
字典 反表 = {v: k 对于 k, v 于 {"甲": "1"}}                   # 键值双变量形式
```

`于` 与 `在` 互为别名，`如果` 与 `若` 互为别名。

### 3.4 模式匹配

```co
匹配 状态码
    情况 1: 输出 "就绪"
    情况 2: 输出 "运行中"
    默认:  输出 "未知"
结束
```

`是` 与 `情况` 互为别名。模式支持整数/浮点/字符串/**布尔**/**列表**/**字典**（结构化判等）。

### 3.5 并发（真线程）

```co
句柄1 = 并发 部分和(0, 1000000)
句柄2 = 并发 部分和(1000001, 2000000)
整数 总 = 等待 句柄1 + 等待 句柄2      # 等待是一元运算符，优先级高于 +
```

`并发 表达式` 创建 pthread 并立即返回任务句柄；`等待 句柄` join 并取回结果。
`并发`/`等待` 是**一元前缀运算符**，只吃紧跟的一个操作数——想并发整个表达式请显式加括号：`并发 (甲 + 乙)`。
引用计数为原子操作，控制流标志为线程局部，共享环境加锁，`make tsan` 保证零数据竞争。

### 3.6 模块与函数前置引用

```co
导入 "标准库"            # 加载同目录 标准库.co，其顶层函数并入当前作用域
输出 是三倍(9)           # 函数可在定义之前调用（顶层函数会被提升）
函数 是三倍(整数 x) -> 布尔
    返回 x % 3 == 0
结束
```

### 3.7 位运算与系统编程

位运算是操作系统、驱动、协议栈、编译器的日常语言。coCN 提供**符号与中文双写法**，
语义与 C 逐位一致，同时把 C 的三处未定义行为全部拦成中文错误。

```co
断言相等(12 & 10, 8)                  # 也可写 12 按位与 10
断言相等(12 | 10, 14)                 # 12 按位或 10
断言相等(12 ^ 10, 6)                  # 12 按位异或 10
断言相等(~0, -1)                      # 按位取反 0
断言相等(1 << 10, 1024)               # 1 左移 10
断言相等(-8 >> 1, -4)                 # 算术右移：符号位持续填充
断言相等(0xDEAD_BEEF, 3735928559)     # 进制字面量 + 下划线分隔
断言相等(十六进制(255, 4), "0x00ff")   # 定宽格式化，便于对照寄存器
断言相等(位计数(-1), 64)               # popcount，按 64 位补码
```

**语义承诺**（每条都有回归用例守着）：

| 场景 | coCN 行为 | C 的行为 |
|------|-----------|----------|
| `1.5 & 1` | 报错「位运算 & 需要整数」 | 编译错误或静默截断 |
| `1 << -1` | 报错「移位位数不能为负」 | **未定义行为** |
| `1 << 64` | 报错「移位位数超出范围」 | **未定义行为** |
| `-8 >> 1` | 恒为 `-4`（算术右移） | 实现定义 |
| `1 << 63` | 补码回绕到最小整数 | 有符号溢出，**未定义行为** |
| `0xFFFFFFFFFFFFFFFF` | 词法期报「整数字面量超出范围」 | 静默回绕 |
| `&&` / `\|\|` | 报错并指引改用 `且` / `或` | 逻辑运算符 |

**字节级视图**：`长度`/下标一律按**字符**（不切碎汉字），而编码、散列、协议解析
必须按字节走，因此另开一套按字节的入口，两套语义各自明确、互不污染。

```co
断言相等(长度("中a"), 2)                        # 按字符
断言相等(字节数("中a"), 4)                      # 按字节（汉字 UTF-8 占 3 字节）
断言相等(字节列表("中"), [228, 184, 173])
断言相等(字节转文本([97, 98, 99]), "abc")
```

`例子/位运算与系统编程.co` 用这套能力实现并校验了：**CRC32**（与 zlib 标准值逐位一致）、
**Base64 编解码**（符合 RFC 4648 补位规则）、**位图筛素数**（空间只占布尔数组 1/64）、
**32 位定长指令编解码**、**IPv4 与子网掩码计算**、**大小端转换**、
**只用位运算实现的加法器与乘法器**——共 60+ 项断言。

## 5. 原生编译（编译成独立二进制）

树遍历解释器永远碰不到内核态——那里没有 libc、没有 `malloc`、没有解释器运行时。
所以 coCN 提供了一条**原生编译通道**：把 `.co` 直接降级成 C，再由 `cc` 产出独立二进制。

```bash
./co --生成C 程序.co 程序.c     # 只产出 C 源码（可读、可二次修改、可接进别的构建）
./co --编译  程序.co 我的程序    # 一步到位产出二进制
./我的程序                      # 独立运行，不需要 co
```

产物是**自包含**的：只链接 libc/libm，不依赖解释器，示例程序编译后仅 38 KB。
生成的 C 保证 `-Wall -Wextra` 零警告，可以放心接进已有工程。

### 5.1 实测性能（`make bench`）

| 负载 | 解释器 | 原生 | 加速比 |
|------|-------:|-----:|------:|
| 斐波那契(27) 递归 | 0.387 s | 0.015 s | **25.3×** |
| 循环求和 200 万次 | 0.653 s | 0.083 s | 7.8× |
| 素数计数 60000 | 0.719 s | 0.086 s | 8.4× |
| 字符串拼接/查找 20 万轮 | 0.382 s | 0.093 s | 4.1× |
| **合计** | **2.141 s** | **0.278 s** | **7.7×** |

函数调用密集的负载收益最大——原生代码省掉了每次调用的作用域分配、
字符串键查找和 `Value` 堆分配。

### 5.2 两条通道的语义必须完全一致

原生后端是**语义的第二套实现**，所以「解释器上测过的代码编译出来行为不同」是最危险的
失效模式。`make native` 把这件事钉死：同一份源码走两条通道，
**stdout 与 stderr 都必须逐字节相同、退出码必须相同**，错误用例必须两条通道都拒绝。
这条门禁进 `make check`，不通过不允许提交。

### 5.3 当前支持范围

| | 内容 |
|---|---|
| **支持** | 整数 / 浮点 / 字符串 / 布尔 / 空、全部算术与位运算、字符串拼接与索引、`如果`/`否则若`/`否则`、`当` 循环、`对于` 循环（含 `步长`）、`跳出`/`继续`、函数定义与递归、全局与局部变量、常用内置（数学 / 字符串 / 转换 / 断言 / `时钟`） |
| **暂不支持** | 列表、字典、张量、并发、异常、模块导入、嵌套函数、函数值、索引赋值 |

不支持的特性会在**编译期**明确报错并指出行列号，绝不会静默产出行为不同的代码：

```
原生编译错误 (第7行,5列): 原生编译暂不支持的表达式节点(类型 12)
原生编译错误 (第9行,8列): 调用 加 的参数个数不匹配：需要 2 个，实际给了 1 个
```

注意第二条：**实参个数不匹配是编译期拒绝的**，比解释器更早发现问题。

## 6. 训练套路（三步法）

```co
让 w = 需梯度(高斯随机([输入, 输出], 0, 0.1))   # 1) 参数需梯度
让 损失 = 均方误差(预测, 目标)                  # 2) 前向得到标量损失
反向(损失)                                      # 3) 自动求导
优化(学习率, [w, b])                            #    更新并清零梯度
```

`反向(损失)` 从损失标量沿计算图反推，自动求出所有 `需梯度` 参数的梯度，**无需手写反向公式**。

### 完整示例：异或网络

```co
让 学习率 = 0.5
让 x = 张量([[0,0],[0,1],[1,0],[1,1]])
让 y = 张量([[0],[1],[1],[0]])

让 w1 = 需梯度(高斯随机([2, 4], 0, 1))
让 b1 = 需梯度(全零([1, 4]))
让 w2 = 需梯度(高斯随机([4, 1], 0, 1))
让 b2 = 需梯度(全零([1, 1]))

函数 前向(输入)
    让 a1 = 双曲正切(矩阵乘(输入, w1) + b1)
    返回 西格莫德(矩阵乘(a1, w2) + b2)
结束

对于 轮 从 0 到 5000 循环
    让 损失 = 均方误差(前向(x), y)
    反向(损失)
    优化(学习率, [w1, b1, w2, b2])
结束
输出 前向(x)   # 接近 [0, 1, 1, 0]
```

## 8. 错误诊断

运行时错误一律带行列号与中文说明，绝不静默出错：

```
运行时错误 (第2行,13列): 无法比较大小: 字符串 < 整数
运行时错误 (第2行,11列): 字符串只支持 + 拼接，不支持 -（字符串 - 整数）
运行时错误 (第2行,9列):  列表索引越界: 10 (列表长度 3)
运行时错误 (第2行,15列): 位运算 & 需要整数，收到 浮点 & 整数（浮点请先用 取整 转换）
运行时错误 (第2行,15列): 移位位数超出范围: 64（0~63）
运行时错误 (第2行,11列): 调用栈即将耗尽（剩余栈空间不足预留量），请检查是否存在无限递归
词法错误 (第2行,8列): 进制字面量中出现该进制不允许的数字
语法错误 (第3行,1列): 多余的 '结束'（单行的「如果 … 则 …」若要写 结束，必须写在同一行）
```

**无限递归**不会变成段错误：栈守卫用 `__builtin_frame_address` 与线程真实栈区间做实时比对，
剩余栈空间低于预留量时抛出可捕获的中文错误。它不是一个写死的层数上限——
真实可用栈越大能递归越深（合法的两千层递归照跑），而且并发线程各自受保护。

**这些错误都可以被 `尝试 / 捕获` 接住**，捕获后解释器状态（引用计数、调用深度、
循环控制标志）必须完全复原——`测试/异常测试.co` 专门守着这一点，ASan 下零泄漏。

## 9. 与 Python 的对比

| 维度 | coCN | Python + numpy/PyTorch |
|------|------|------------------------|
| 语法 | 全中文关键字，贴近自然语言 | 英文 |
| 依赖 | 单文件 C，零依赖 | 需安装 numpy / torch |
| 类型 | 渐进式静态标注，运行时强制检查 | 注解不强制 |
| 张量 | 内置 `张量` + `反向()` 自动求导 | `torch.Tensor` + `loss.backward()` |
| 并发 | `并发`/`等待` 真线程，无 GIL | 受 GIL 限制，需多进程 |
| 位运算 | 完整位运算 + 进制字面量 + 字节视图；C 的 UB 全部拦成中文错误 | 有位运算，但整数是任意精度，`<<` 不会回绕 |
| 原生编译 | `co --编译` 产出 38 KB 独立二进制，只依赖 libc/libm | 需 Cython / Nuitka 等外部工具链 |
| 质量门禁 | ASan/UBSan/TSan 零容忍 + 原生双通道逐字节一致 | — |
| 性能 | 解释执行适合小模型/教学；`--编译` 后标量与控制流负载快 7.7×（递归 25×） | 编译/CUDA，适合大规模训练 |

**结论**：coCN 不是要取代 PyTorch，而是提供一种「中文即可编程与建模、零依赖即跑」的轻量选择，
特别适合中文教学、算法原型，以及不想被英文 API 与庞杂依赖劝退的场景。
原生编译通道则让它有机会走出脚本范畴——目标是系统与内核级代码。
